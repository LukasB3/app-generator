How it stays safe

Every request is treated as hostile. The design assumes the agent can be talked into anything and makes sure that would not matter.

Requests are screened first
A small model reads each request before it is queued and turns away gibberish, abusive text and requests that carry personal data. Nothing below relies on it getting that right.
The agent can write files and ask for tables
It runs in a throwaway container with no shell, no git and no route to the internet. For an app that shares data it can ask for tables in a database. The container is deleted after every job.
It never holds a real key
The container gets a pass that works for one job and expires with it. A separate proxy swaps it for the real API key, which the agent cannot read.
Plain code decides what gets published
A checker with no AI in it inspects every file: allowed types, size limits, no secrets, no outside scripts, no forms that send data anywhere.
Nothing is created before the check
A wish for a table is only written down. The tables are created after the app has passed the checker, by code that builds every database statement itself.
Published apps are boxed in
Each page carries a policy that stops it from loading or contacting anything outside its own folder, and a badge marking it as generated. An app that shares data may reach its tables and nothing else.
Live data comes through one narrow door
An app can show the weather and exchange rates. It asks this site's server, which knows four fixed questions and passes on only the numbers it expects.
Shared data is public, and says so
What visitors enter into such an app can be read by everyone, and the page tells them. A table stops at 500 small rows and is deleted together with its app.
Publishing is a separate, narrow step
Ordinary code pushes the checked files with a key that is valid for one repository and nothing else.
Costs have a ceiling
One job at a time, a hard time limit, a token budget per job, limits per visitor and per day, and a captcha in front.
